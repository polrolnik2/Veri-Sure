# fpu_exceptions: qualitative error analysis (19 designs: 15 generated, 4 repaired; luna14 has no r0)

**Method.** Open-loop traces of all designs on all 4 stimuli. **Every number below is restricted to the 1,721 testpoints whose first stimulus step is a reset step** (48–57 % per corpus, using the same predicate as `is_reset_step`), and to edges after each testpoint's first reset row. The restriction removes state carried over from the previous testpoint.

The traces are cut into constant-input segments of 12 edges or more (1,718 segments). Every segment is longer than golden's deepest path, so the last edge gives the settled function. Each port-edge mismatch is labelled: a functional mode (the settled values differ), **timing** (the settled values agree), **unsettled** (the segment is shorter than 12) or **reset row**.

Scripts are in `qual/fpu_exceptions/`: `rs.py`, `settle.py`, `modes.py` (run with RS=1), `share.py` (RS=1), `h2_rs.py`, `closed_rs.py`, `latency_rs.py`. Unrestricted results are kept beside them, e.g. `share.json`.

Correct in all 19 designs at steady state: overflow and rounding-mode infinity vs max-finite, and mantissa_in inexact. The rounding and inexact definitions are not where the designs fail.

**Why, classification (a/b/c), and whether the run encoded it**
- **LAT/L0.** *Cause:* the designs read "registered" as one register stage, or one aligned pipeline (luna14.gen3: uniform 4). "Not a new multi-stage pipeline" pushes the same way. *Class (b):* golden's skew follows if every listed internal `reg` is a flop and each equation reads the registered names it mentions. The spec supports this (see §4) but never states the depths. *Encoded:* yes. The luna12/13 ref models are 1-cycle and the luna14/15 ones are uniformly 4-cycle; none has golden's skew.
- **M1.** *Cause:* the spec says "quiet" twice and defines quiet as bit 51 set. *Class (c):* golden's 01 pattern is a signalling NaN by the spec's own definition. The reg name `SNaN_trigger` is too weak a hint to outweigh that. *Encoded:* yes. All 4 ref models emit 7ff8…, and every run's shipped NaN-pattern check (luna12 REQ-0158, luna13 REQ-0159#1, luna14 REQ-0157, luna15 REQ-0159) *requires* bit51=1, so golden would fail them.
- **M2/M3.** *Cause:* IEEE intuition: inf, NaN and x/0 results are exact, so "underflow" must mean a tiny finite result. The generator added guards the text does not state. *Class (a), (b) for M2a;* see §4. *Encoded:* M2a/b/c are in all 4 ref models. M3 is not in any of them (there the ref equals golden).
- **M4.** *Cause:* the generator followed the overview sentence. *Class (b), favouring golden:* the detailed paragraph and the selection order ("First … the normal rounded result or signed zero for underflow") are unconditional. *Encoded:* no. The ref models equal golden, and the checks see it (luna13 REQ-0142/0150; luna15 REQ-0143/0152/0161).
- **M5.** *Cause:* the generator equated ex_enable with the `exception` summary, which is described in the sentence just before it. *Class (a):* a QNaN input must be overridden ("If either input is a QNaN, the output is a QNaN"). *Encoded:* no. The luna12 ref equals golden. luna12.gen1, gen2 and r0 all fail REQ-0001; in the r0 log that check fails at TP-0011 (QNaN+num) on ex_enable.
- **RST/X.** These are repair artefacts. *RST, class (a):* the editor log says "Clearing the outputs immediately when reset is asserted would violate that requirement". It still made the change, chasing checks that expect zeros in the reset row; the fresh-model ref reads 0 there. *X:* an unindented second `assign stage0_d` on an already-driven wire.

## 2. Hypotheses

- **H1 SUPPORTED.** The finals' remaining errors (M1, M2, LAT) are silent or inverted in the checks. luna12.final passes 136/137 checks while showing M1 on 57 of its 460 own segments. The REQ-0149 underflow check would catch M2, but its testpoints (TP-0632–0637) never use inf/NaN operands. The generated-only modes M5, M4/M4b and M3 were check-visible and were repaired. Two exceptions: luna15 (visible, but the patch produced X), and luna13.final, which keeps M3 because luna13's stimulus never exercises 0/inf.
- **H2 SUPPORTED.** Each final's settled-mode profile, L0 included, equals its run's ref-model profile exactly (luna12/13/14). luna15 differs only where the final has X instead of M4. Repair removed only modes where ref = golden. At the 1,892 port-edges where luna12's r0 and final differ, final always agrees with ref: ref only 59 % (981 of them are the `out` latency going 3→1), both 40 % (707 are the M5 fix), golden only 0 %. luna13: 185 changes, 76 % to both, 24 % ref only. luna15: 36 changes, none to either (X). *Caveat:* BEHAVIOUR's +21.8 ref / +2.1 golden for luna12 is carry-over-inflated. Unrestricted, the async reset alone added 1,378 reset-row edges that "matched" the fresh-state ref.
- **H3 SUPPORTED.** M1, M2a, M2b, L0 and LAT appear in 19/19 designs and in every ref model. Their sources: one sentence that contradicts golden, one IEEE habit, one unspecified depth.
- **H4.** Fixes: M5 and M3 (luna12), M4/M4b (luna13). Breaks: luna12's `out` latency collapse (981 G→R edges), luna15's `out` becoming X on 10 segments, and luna12's async reset, which violates the spec but changes behaviour on at most one edge per testpoint. The luna12 closed-loop collapse in latency_report §E (order-only 24.4→14.3 %) is a **carry-over artefact**: restricted, luna12.final's per-port functional mismatch is 6.5 % against 7.8 % for r0, and identical to luna12.gen3.
- **H5 SUPPORTED (local patches).** luna13: a one-line guard. luna15: one bolt-on assign. luna12: 7 hunks (an equation rewrite, a guard deletion, folding the `out_0/1/2` chain into same-cycle logic, gating probe values, async reset). The finals land in behaviour classes that fresh samples also produce (luna14.final ≡ luna12.gen3; luna13.final ≡ luna14.gen1/gen2). Only RST and X are unique to the repaired arm.
- **H6 REFUTED.** Closed loop, per port, restricted: the finals are 40.8 % exact, 51.9–52.0 % timing-only, 6.5–6.6 % functional. The generated designs are 6.4–7.8 % functional. Whole-testpoint dedup cannot separate the arms: about 71 % of testpoints "differ" for every design, because golden's per-path skew creates intermediate flag combinations.

## 3. Qualitative difference between the arms

The settled function hardly differs. Repair only removes check-visible minority modes where the ref agrees with golden (M3–M5), and that converges every final onto its ref model's reading, M1 and M2 included. The one difference in kind: the two errors only repair produced (an async reset and a multi-driven X) are check-chasing artefacts that break explicit spec text or basic RTL hygiene. No generated design has either. Behaviourally, the async reset is almost invisible once carry-over is removed.

## 4. Justifiable readings (share of generated-arm disagreement, restricted)

1. **Every listed internal `reg` is a flop in one enabled clocked block; each equation reads the registered names it mentions, and raw ports otherwise.** Justification: "fully registered"; every internal signal is declared `reg`; "Stage-0/1/2 pipeline copy"; "registered intermediate results … First … Next … Finally"; "including the registered timing and trigger equations". Read "no new pipeline" as "no stages beyond these regs". Share: **up to 78.7 %** (timing, unsettled, L0). This is an upper bound: I did not build a design from this reading, and some raw-vs-registered operand choices are still guesses.
2. **Use only the qualifiers the spec states.** "nonzero" means the spec's zero test (bits [62:0] ≠ 0), so inf and NaN count. "finite" includes 0. "nonzero division" means a nonzero dividend, as in the spec's own "nonzero division by zero". The neighbouring equations spell out "provided there is no NaN input" and the underflow sentence does not. Share: **2.6 %**.
3. **ex_enable means "the output is overridden"**, and NaN propagation is an override: **2.1 %**.
4. **Where the overview and the detailed paragraph conflict, the detailed one wins** (underflow forces signed zero): **1.0 %**.
5. **Synchronous reset as written:** less than 0.1 % here (at most the first reset row of each testpoint).

With all five, about 84 % of the disagreement can be closed. The floor is **M1 (15.7 %)**: no justified reading reaches golden's 7ff4 payload.
