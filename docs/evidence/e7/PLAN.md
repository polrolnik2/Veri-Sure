# Generalising off one module

Everything measured on this branch is `i2c_master_bit_ctrl`. Three more modules,
to find out which results are the pipeline's and which are that module's.

## What can and cannot be measured there

**AUDIT IS UNAVAILABLE ON THE NEW MODULES, AND THAT IS NOT A CHOICE.** The
audit column needs a control, and `benchmarks/controls/README.md` says what a
control is: "a line-by-line transliteration of
`.../i2c_master_bit_ctrl.v`". Only that module has one. Writing another means
reading the golden design for the new module, which is barred here.

So on the new modules the triple is a PAIR:

    span        measurable -- requirements minted against checks frozen
    blindness   measurable -- the spec-derived population reads no reference
    audit       ABSENT, and reported as absent rather than as 0

That limit is worth stating loudly because `audit = 0` is the leg every
selection rule on this branch was barred from tuning against. On these modules
nothing can tune against it because nothing can see it -- which makes span and
blindness a cleaner read, not a dirtier one.

## The three

| module | spec | shape | contract |
|---|---|---|---|
| `i2c_master_byte_ctrl` | 19.4 KB | HIERARCHICAL, instantiates the bit controller | author + `child_assumes` |
| `or1200_dc_fsm` | 13.0 KB | flat cache FSM | author |
| `or1200_ctrl` | 14.3 KB | flat control, a different subsystem | `benchmarks/baselines/or1200_ctrl/arm_a` exists |

`or1200_ctrl` is included BECAUSE its contract already exists: it removes
contract authoring as a confound from one of the three, so if the other two
behave differently there is a way to tell whether the contract or the module is
responsible.

`or1200_dc_fsm` is the module this tree has the most recorded history on --
k1-dcfsm, 87 requirements, the 83.9% span ceiling, 25 ABANDONED of which 18
were silenced in `_unreached`'s guards. A prior to compare against.

## The hierarchy conversion

From the specification, never the RTL: "the module instantiates
i2c_master_bit_ctrl with the instance name bit_controller", connected through
`core_cmd`, `core_txd`, `core_ack`, `core_rxd`, with `i2c_busy`, `i2c_al` and
the SCL/SDA lines generated by the child.

So its contract needs `child_assumes` for `i2c_master_bit_ctrl` -- the key
`_EditSession` reads for `child_names`, which gates the vestigial-glue rollback
and tells the editor which outputs belong to a child rather than to the design
it is editing. Without it a hierarchical module is edited as though the child's
behaviour were its own.

## Order

Not started until `full10` reports. A pipeline that has not met the target on
the module it was tuned on cannot learn anything from three more.
