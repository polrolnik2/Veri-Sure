# or1200_sb: checks-only vs model feedback (luna12/13/14)

**Verified.**
- The luna13 and luna14 starts pass ChipVerilog by induction.
- The luna13 checks final is byte-identical to its start.
- The luna12 start has no `` `ifdef ``: it hard-wires the enabled store buffer (mode A). Its formal verdict is a memory-import error, so its non-equivalence rests on traces.

**Notation.** Counts are open-loop edges on the run's own stimulus: g = equal to golden, ref = equal to the run's ref rows, Δ = edges where the final differs from the start. Analysis scripts ran in a scratch directory and are not committed (their outputs embed the editor's reasoning). Mode labels A1–A4 are those of `../qualitative/or1200_sb.md`.

**Correction to the setup.** Ties also latch "ON THE GRADIENT" (`eda_agent/rtl_editor.py:2131`). The gradient is check instances in the checks arm and model testpoints in the model arm. 4 of the 9 model-arm latches were gradient-only. Each checks arm's gradient was 0 after its one latch.

**Why the checks arm stalled (from its log; the editor's words are paraphrased).**
- `_tool_find_signal` ignores the preprocessor. It reports a signal driven in both arms of an `` `ifdef/`else `` as having 2 drivers that "resolve to X". The session reproduced this on a toy module. The tool is wrong: the arms are mutually exclusive.
- So the editor deleted stubs that were in fact the live drivers. That left the score unchanged, or broke probes.
- It weighed defining the macro and declined, reasoning that this would alter behaviour the contract fixes.
- It also believed it could only edit inside suspect blocks, and a directive is not a block.
- The 3-round cap ended the run with 11 trials left.
- The model arm went down the same path, then defined the macro after noting that the reference model it was shown defaults the feature to enabled. That is ref13's default.

## How the arms differed

**Both feedbacks pull toward the enabled build.** The checks themselves demand FIFO activity ("fifo_rd was 0, but ~outstanding_store was 1"). So root cause 1 survives without the model.

**After the pass count peaks, the arms split.**
- **Checks arms make the minimal check-satisfying move and stop:**
  - luna12: one invented qualifier;
  - luna14: a `` `define `` that turns on a latent, buggy branch;
  - luna13: nothing.
- **Model arms keep latching on the model gradient** and transcribe details the checks cannot see: depth 16, `fifo_last`, payload hold, async reset.

**Effect on behaviour.**
- Model finals equal the ref model on 100% of changed edges.
- Checks finals equal it on 24% (luna12) and 28% (luna14). They took different routes to the same checks and produced different wrong behaviours (A3 vs A1).
- No edited arm moved a single edge toward golden.

**Artefacts.**
- Three arms made the configuration move, each with `_tool_edit` on a non-block line, against "You MUST only modify code inside suspect blocks".
- Two model arms left dead logic.

**luna13's checks arm was not protected by the feedback.** Macro-blind tooling and a rule it obeyed kept it at golden; the model arm broke through with a ref-model cue.
