# Hardening the Testbench: A Research Synthesis for Veri-Sure

## 1. The real problem

In Veri-Sure an LLM writes the testbench, and that testbench is simultaneously **(a) the correctness oracle** and **(b) the only channel through which a failure is described to the repair agent**. Both roles fail independently, and the literature has names for most of the failures — but they are scattered across four fields (EDA verification, formal methods, software testing, agent evaluation), which is why the team has been rediscovering them one incident at a time.

The single most useful framing is Barr, Harman, McMinn, Shahbaz & Yoo (IEEE TSE 2015). A test oracle `D` approximates a ground truth `G`. It is **sound** iff `D(a) ⇒ G(a)` and **complete** iff `G(a) ⇒ D(a)`, and — their words — "test oracles cannot, in general, be both sound and complete." Every one of Veri-Sure's TB failure modes is one of those two halves, and **the two halves need different gates and different repair routes**.

| Veri-Sure failure mode | Literature term | Class | Mechanical detector |
|---|---|---|---|
| Oracle mirrors the DUT's algorithm ("two copies of the same bug") | **Coupled Validation Failure** (RefEvo, ISEDA 2026); **misguidance effect** (Zhao et al., ISSTA 2026) | Unsound | Mutate the RTL; a mirrored oracle kills few mutants |
| Oracle is over-constrained / self-contradicting; fails a CORRECT DUT | **Incomplete oracle**; **candidate-specific evidence** (Xu & Wu 2026 measure 26.9%) | Incomplete | Run the TB against golden / last-passing RTL ("reference precheck") |
| Checks are DEAD: static-init nulls the compare, print-only check never feeds the mismatch counter, scenario unreachable | **Vacuity / antecedent failure** (Beer, Ben-David, Eisner & Rodeh 2001); **detection-stage failure** (Huang et al. 2015); Certitude's *"activated and propagated but not detected"* | Unsound | Coverage on the mismatch-counter line; mutation kill rate |
| Verdict parsed from log markers; an unrecognised PASS phrasing scores as a design failure | **No published term.** Nearest analogues: ChipVerilog's `reference_fail`, GateTruth's disclosed fail-open bug, Weyuker's "non-testable program" (1982) | Neither — a *harness* fault | Liveness check: the TB must print an accepted marker on a known-good DUT |
| Failure log carries no expected-vs-actual, no cycle, no minimal stimulus, no localization | **Non-actionable execution feedback** (ISSTA 2026: only 48.8% of Claude Code reproduction runs actionable); missing **admissible alternatives** field (Ray & Goyal 2026) | Channel | Classify every run `{actionable, env_error, uninformative}` before computing a verdict |
| Toolchain/lowering error names no line of the TB, blame lands on the RTL | **Environment error** (15–34% of validation runs in the same study); **stillborn mutant** discipline (GateTruth) | Channel | Typed diagnostic structuring, not regex inference |
| TB passes but never exercised the interesting states | **Stimulus Gap / Sequence Gap / State Unreached** (GoGoTB); **methodology-bound ceiling vs reasoning frontier** (CovAgent) | Adequacy | Coverage + formal unreachability discharge |
| Agent edits the RTL to satisfy a wrong TB | **Test overfitting** (Smith et al. 2015; Ahmed et al. FSE 2026); **reward hacking** (SpecBench) | Loop | Held-out checks; in-loop vs held-out pass-rate gap |

Two numbers set the stakes. Bodicoat et al. (AIware 2025) measured LLM oracles at **70.84% buggy-failure rate but only 58.13% correct-pass rate** — roughly four in ten generated oracles reject a *correct* implementation. And Xu & Wu (2026) found **46.0% of the positive validation events an LLM repair agent relies on carry no bug-discriminating information at all**. The false-FAIL direction is not a secondary concern; it is comparable to or worse than the false-PASS direction, and it is the one that burns iterations.

## 2. Themes

### 2.1 Oracle trustworthiness and independence

**Established.** Independence-by-prompting does not work, and the cause is mechanical, not motivational. Zhao et al. (ISSTA 2026) generated unit tests from buggy vs fixed implementations of the same method: **137.69 misguided tests (3.84%) from buggy code vs 16.46 (0.46%) from fixed code** — an 8× increase in assertions that encode the bug — while effective tests collapsed from 304.08 to 104.15. Their fix is a prompt-*composition* change: delete the implementation from the prompt and substitute a generated behavioural specification (recovering effective tests to 186.77). The presence of the implementation in context is itself the corrupting influence.

Three independent architectural lines then say the same thing from different directions. AutoSVA2 (Princeton) found GPT-4 writes correct SVA *for flawed RTL* "without mirroring design errors" — because AutoSVA properties are derived from annotated port declarations, never the module body. GoGoTB (ICCAD 2026) enforces it as an information barrier: "the reference model is derived from the specification alone and has no visibility into RTL implementation details," so "any simulation mismatch cannot originate from a corrupted oracle." Spec2Assertion generates pre-RTL, when there is nothing to mirror.

**Contested.** Whether sampling buys independence. CorrectBench validates a TB with no golden by running it against ~20 independently generated RTLs and indicting the *testbench* on any scenario ≥70% of them fail (88.85% validation accuracy; TB pass ratio 33.33% → 52.18% → 70.13% across direct/AutoBench/CorrectBench). Against that: Knight & Leveson (1986) rejected the independence null at α=0.01 with **z = 100.55** across 27 versions and 1M tests; Ron, Baudry & Monperrus (2026) replicated it with 48 coding-agent implementations of the *same* Launch Interceptor spec and found "substantial common-mode failure" (though voting still helped: mean failures 387.44 → 130.99 for 3-version units); and Kim et al. (ICML 2025) measured **60% same-wrong-answer agreement** across 350+ LLMs, with correlation *rising* for larger and more accurate models even across distinct providers.

The synthesis of those three: **model-swapping does not decorrelate, and gets less effective as models improve.** Ron et al. localise the residual correlation at *specification ambiguity* — which makes `contract_linter.py` the highest-leverage decorrelation tool in the repo, not a side quest. The only real decorrelation levers are structural: change the abstraction level (transaction-level model vs cycle-accurate reimplementation), change the oracle *type* (metamorphic or implicit rather than value-comparison), or change the authority (a formal property from the contract).

**Unknown.** Nobody has measured correlated failure for LLM-generated *RTL specifically*, and nobody has measured the rate at which a generated TB and a generated RTL from the *same contract* share a defect. That is the number Veri-Sure most needs and it is cheap to obtain on ChipVerilog.

### 2.2 Mutation and fault injection as testbench grading

This is where the arXiv-only view was wrong. Three prior passes concluded "no cost model for in-loop mutation exists" and "mutation score has never been an online admission gate." **Both conclusions are artefacts of not searching the commercial EDA literature.** Mutation-based *functional qualification* has shipped for ~20 years (Certess → SpringSoft → Synopsys Certitude).

**Established — the four-status verdict.** Busch (DVCon 2013, Infineon AURIX) documents Certitude's per-fault outcomes verbatim: a fault is (1) not activated by any test, (2) not propagated to an observable point, (3) activated and propagated but not detected, or (4) detected. Hampton (Certess CTO, EDN 2009) states the three necessary conditions the same way. **This is a repair-routing table, not a score:** not-activated → stimulus; not-propagated → observability/TB structure; not-detected → the checker is dead or too weak; detected → the check is live. Huang et al. (*VLSI Design* 2015) add a second observable — whether coverage *fluctuates* between golden and mutant — giving a 2×2 that separates "missing coverpoint" from "deficient checker," and a composite score with a stopping threshold (weights 0.2/0.4/0.4, threshold 0.9; reached in 6–10 iterations, 3–7 hours on two designs).

Huang's `compact_factor_che = (#fired checkers)/(total #checkers)` is worth calling out: **a checker that never fires across the whole mutant campaign is scored as redundant.** That is a mechanical detector for the exact failure Veri-Sure's SYSTEM_PROMPT currently forbids by instruction.

**Established — the cost model exists.** Four independent mechanisms, and they compose:
- **Sampling.** Leveugle et al. (DATE 2009): `n = N·t²·p(1−p) / [e²(N−1) + t²·p(1−p)]`. For N = 4,063,170 faults, 95% confidence at ±5% margin needs **385 injections**. Margin dominates cost (±1% → 9,581); confidence is cheap (99% → 663). Sample size is essentially independent of population size, so an in-loop gate costs a *fixed* ~40–100 runs per node.
- **Pre-qualification.** Busch: faults not activated-and-propagated never reach the expensive detection run. Under Verilator this is free — a byte-diff of mutant vs golden stdout/VCD.
- **Fault dropping.** If a mutant on an enclosing `case`/`if` is undetected, every nested mutant is undetectable; drop them without simulating.
- **Equivalent-mutant filtering.** Papadakis et al. (ICSE 2015) compile mutant and original and compare output: **7.4% equivalent, 21% duplicate, <3s/mutant**, catching ~30% of true equivalents. The RTL analogue is *stronger* and Veri-Sure already owns it: a Yosys/SymbiYosys equivalence check proves a mutant unkillable, so it leaves the denominator by construction — no hand-maintained exclusion table (GateTruth's own exclusion table was wrong for 36 of 72 entries).

**Established — mutation predicts, coverage does not.** Zhao et al.'s ISSTA 2026 replicability study: **raw** mutation score correlates r = 0.863 (p<0.001) with real-bug detection across models; **normalized** mutation score only r = 0.493 and not significant; coverage measured on *buggy* code is "uniformly weak across all three views." Gate on raw kill count, never on coverage-against-the-candidate.

**Established — weak oracles are the norm.** GateTruth's audit of RTLLM v2.0: 46 auditable designs, all of which pass their own reference testbench, yet **pooled kill rate 56.8% (440/775 mutants), median 74.0%, 72% below a 95% floor, three designs at exactly 0%** — including one where inverting the primary output still passes. Independently: BugGen found 104 previously-undetected bugs in OpenTitan's *own* regressions; Rajan (2026) found 28.5% of audited SWE-bench Verified tasks accept a Docker-verified *incorrect* patch, with models scoring +14.14pp on those tasks.

**Contested.** The threshold. GateTruth argues 95%; HardSecBench admits benchmark tasks at ≥50%. And GateTruth self-reports **a Goodhart effect on testbenches revised to pass its own gate** — which is decisive for design: the mutant set shown to `tb_editor.py` must be **disjoint** from the mutant set that gates admission, or mutation gating becomes a more sophisticated form of the reward hacking it was meant to prevent.

**Unknown.** Whether kill rate discriminates *two same-model TBs for one node* — Zhao et al.'s r = 0.863 is an inter-model result and the intra-model correlations were weak. Also: no validated SystemVerilog mutation operator set with per-operator kill statistics exists anywhere. And mutation gating presupposes a golden; mutating the *candidate* measures the TB's sensitivity to that candidate, which still catches dead checks and mirrored oracles but is not a correctness gate and must be labelled differently.

### 2.3 Coverage as feedback, and stimulus adequacy

**Established — coverage is a progress signal, not a selection signal.** Böhme, Szekeres & Metzman (ICSE 2022, ~13 CPU-years, 10 fuzzers × 24 programs): Spearman ρ > 0.90 between coverage and bugs found, but Cohen's κ for *which tool is superior* is only weak-to-moderate (mostly 0.23–0.63). Inozemtseva & Holmes (ICSE 2014) show why: control for suite size and coverage's correlation with fault detection drops to low-moderate. An agent rewarded on coverage will add stimulus — the cheapest way to raise the number without strengthening the oracle. **A mirrored oracle can reach 100% line coverage and kill zero mutants.**

**Established — format matters, measurably.** VerilogReader ran the ablation: raw Verilator coverage DB (coverpoint-id + hitcount) < `verilator_coverage --annotate` < a report flagging *only uncovered lines* with an explicit "TO BE COVERED" marker. Same information, different cycles-to-close. The general rule across VerilogReader, LLM4DV, GoGoTB and CovAgent: give the agent the **delta and the diagnosis**, never the full state dump.

**Established — an uncovered bin needs a root cause.** Two 2026 systems converged independently. GoGoTB: Stimulus Gap / Sequence Gap / Cross Hole / State Unreached / Timing Dependent / Transition Gap / Seed Insufficient, each routed to a specific remedy (I2C case: 10/6/3/2/1/1/1 of 24 residual bins). CovAgent adds the orthogonal split that matters for *termination*: methodology-bound **ceilings** (tied-off 4.1%, infeasible boundary 0.01%, dead code 2.7%) versus reasoning **frontiers** (protocol sequencing 40.2%, multi-module pipeline warm-up 49.9%, narrow timing 2.3%). Both agree the residual is dominated by **sequencing**, not single-value stimulus.

**Established — the cost profile is counterintuitive.** CovAgent instrumented an agentic coverage loop and found **only 12–18% of tokens produce testbench code**; the rest is comprehension, reasoning, feedback and infrastructure, with reasoning-token density rising from ~0.1–0.3/LOC (small designs) to ~4–8/LOC above 2000 LOC. **~50% of all tokens are spent after the 95% coverage milestone.** A domain-specialised agent with structured feedback beats a generic-shell agent by 4–13× in tokens at equal or higher coverage. So the leverage is caching design comprehension across iterations (the DUT is stable within a node), not shortening the emitted testbench — and coverage should be an **admission gate**, not an objective to maximize, since Bennett & Eder's review notes CDG-generated tests are "longer, less targeted, and use more simulation resources to achieve the same result."

**Contested.** Whether the LLM should emit vectors or a *plan*. HAVEN's answer is unambiguous: "LLMs should not write HDL testbenches directly" — the LLM emits structured JSON, Jinja2 templates render the UVM, template components form a **protected set** the repair loop may never touch, and compilation success is **100% across 19 designs (180–11k LOC) at ~6 LLM calls and $0.37 per design**, reaching 90.6% code / 87.9% functional coverage. STG reaches the same conclusion deterministically: template-derived testbenches caught **236 incorrect DUTs the LLM approach passed, 193 of them outright false passes**, with toggle coverage 95.77% vs 85.40% (line coverage differed by only 1.9 points — **toggle is the metric that discriminates weak LLM testbenches**). HAVEN's own failure mode is the warning: a *linear* DSL hit an expressiveness ceiling on 15.8% of designs, so any Veri-Sure stimulus DSL needs loops, conditional stalls and backpressure from day one.

**Unknown.** Coverage-directed generation (Fine & Ziv's Bayesian networks, NOVA's Bayes-optimized constraint-solver branching probabilities, Masamba et al.'s test selection) all presume a stimulus generator **with knobs**. Veri-Sure has none — `tb_generator.py` emits a one-shot procedural program, so 23 years of CDG literature is simply unavailable. Also unavailable: Verilator has no constrained-random solver, so NOVA-style solver tuning requires moving stimulus into Python (cocotb / PyVSC) driving a Verilator-built DUT. GoGoTB chose exactly that stack, and stated they chose cocotb "because LLMs produce substantially lower first-pass correct code in SystemVerilog."

### 2.4 Formal adjudication: bounded proofs, vacuity, unreachability

**Established — a bounded run is not a proof.** Kroening, Ouaknine, Strichman, Wahl & Worrell (CAV 2011): for `Gp` the completeness threshold is the diameter, for `Fq` the recurrence diameter, and "determining its value is clearly at least as hard as solving the original model-checking problem in the first place." ChipVerilog's **383 `bounded_seq` vs 48 `strict_comb`** verdicts therefore carry no completeness claim. SymbiYosys already distinguishes the two: `mode prove` runs k-induction and returns an **unbounded** pass/fail/UNKNOWN; `mode bmc` does not. Veri-Sure should record three formal verdicts — proved / bounded-clean-to-depth-k / refuted — not two.

**Established — vacuity is the formal name for the dead check.** Beer et al. (FMSD 2001) and Kupferman & Vardi (STTT) define a property as vacuously true when a subformula can be replaced by a constant without changing the verdict, and prescribe an **interesting witness** for every pass. The mechanical antidote is one line: for every `assert (A |-> B)` also emit `cover (A)`. An assertion whose antecedent is unreachable did no work — it is DEAD, not PASSED. `asserter.py` and `boolean_proofer.py` can do this today. The open-source multi-agent SymbiYosys/Z3 pipeline (arXiv 2607.28877 — Veri-Sure's exact stack) names the corresponding false-FAIL mode: **"bounded-cover vacuity"**, where a *correct* design was flagged failed because reaching a wrap-around state needed ≥256 cycles and the cover was unreachable at default depth.

**Established — unreachability can be discharged, and industry does.** Synopsys ships formal UNR (VC Formal Coverage Analyzer): prove the target unreachable, emit an exclusion file, correct the coverage denominator. Meanwhile **every LLM coverage paper surveyed gets this wrong**: GoGoTB "removes structurally unreachable bins from the denominator" with no stated criterion; CovAgent states plainly that its M1–M3 ceiling assumption "is not validated through formal reachability analysis"; NOVA reports AXI4 results "deflated" by unreachable bins; CHORUS ignores it. **This is Veri-Sure's clearest opening** — it already runs SymbiYosys, so it can prove a bin unreachable rather than assert it.

Note the asymmetry: `sby mode cover` finding no trace within depth k proves only "not reachable in k cycles." To prove unreachability you assert the negation and discharge with `mode prove`.

**Contested.** Whether formal can adjudicate a *simulation testbench*. Every adjudication mechanism found operates on assertions (declarative objects a prover can reason about) or on whole-design equivalence. A procedural self-checking SystemVerilog TB is not a formal object anywhere in this literature. **The realistic path is not to formalise the TB but to run a second, formally-adjudicable oracle alongside it and use disagreement as the blame signal** — where formal equivalence proves a design correct and the TB nonetheless fails it, you have a free proof that the *oracle* is wrong. Nobody publishes this cross-check; GateTruth explicitly *separates* formal kills from simulation kills and discards exactly this signal.

**Unknown.** AssertLLM reports 89% of generated SVAs syntactically and functionally correct; AssertionBench reports no LLM exceeding ~44% validity with up to 63% producing counterexamples. Either way, `sim_reviewer.py` coerces assertion failures to `mismatch_cnt=1`, so **a hallucinated assertion currently reads as a design bug**. Assertions need the same admission gates as testbenches.

### 2.5 Failure-report design and repair-loop control

**Established — localization alone buys almost nothing.** Ray & Goyal (2026) ablated a failure report into `{location, observed value, admissible alternatives}`. Feedback with only location + observed value performs **near the raw-diagnostic baseline**; essentially all of the +42 to +44pp gain came from the third field — *the set of values that would have been accepted*. Prose vs keyed JSON made no difference. Veri-Sure ships the first two fields.

**Established — relevance beats volume, and the cost of noise is measured.** DebugRepair: removing its test-semantic-purification step dropped correct fixes from 224 to 164, a **26.8% loss purely from irrelevant context**. ReduceFix: 89.1% average input reduction gave **+53.8% relative pass@10 versus including the original input** — and, critically, including the raw input was **worse than including no input at all**. That is a direct warning about feeding whole sim logs to `rtl_generator.set_failed_trial()`.

**Established — channel ranking, and Veri-Sure's TB loop runs on the worst channel.** FeedbackEval on identical bugs: Mixed 63.6% > LLM-Expert 62.9% > Test 57.9% > Minimal 53.1% > **Compiler 49.2%** > LLM-Skilled 48.8%. The TB repair loop at `top_agent.py:628-648` is lint-driven — the weakest non-trivial channel — while the RTL loop gets the sim log.

**Established — repair loops saturate at ~3 iterations, and accumulating history hurts.** FeedbackEval plateaus after 2–3; "Is Three the Magic Number?" finds the first 3–4 iterations account for most gains, and — the strategic claim — "repair behavior is influenced more strongly by workflow orchestration and feedback design than by the underlying model itself." LLM4DV's dialogue-restart scheduler wipes history when fewer than 3 new bins are hit in *t* responses, because "LLMs sometimes behave stubbornly, repeating mistakes they made previously." **Veri-Sure's lint loop does the opposite: it accumulates errors across retries.**

**Established — repairing against a generated oracle and judging with the same oracle is circular.** Smith et al. (ESEC/FSE 2015, 998 bugs): patch quality is proportional to the coverage of the suite used *during repair*; for programs passing most tests "the tools are as likely to break tests as to fix them"; and requirements-based (black-box) tests overfit significantly less than generated (white-box) tests — a 2015 vindication of contract-derived oracles. Ahmed et al. (FSE 2026) measure the LLM version: test-based refinement raised the apparent fix rate but raised **overfitting from 21.8% to 25.5%**, with **14 of 22** apparently-successful refinements failing hidden tests. Smith et al.'s prescription is directly implementable: withhold a portion of checks from the repair loop; the in-loop minus held-out gap *is* the overfitting number.

**Established — do not reach for an LLM judge as the primary fix.** "From Confident Closing to Silent Failure" (FAGEN@ICML 2026): LLM judges detect silent false success at **AUROC 0.54–0.65** — near chance — because they key on "confident closing language," which is precisely what a marker like `SIMULATION PASSED` is. Cheap calibrated mechanical detectors scored 0.83–0.95 at 3,300× lower latency. The same paper gives the strongest general-agent argument for oracle independence: false success is **45–48% of failures in single-control settings but 3% in dual-control settings** — a ~15× reduction from splitting who does the work and who judges it.

**Contested.** Where a judge *does* pay. PRO-V's blame-attribution judge (RTL bug vs TB bug vs toolchain) lifted golden-RTL acceptance 87.17% → 89.7%; EvilGenie found an LLM judge beat held-out tests for detecting unambiguous reward hacking; Meta's production agent gates patches with an LLM judge. The pattern across all three: **LLM judge proposes, executable ground truth gates** — Rajan's Docker gold gate caught 61.9% of defective test-generation attempts the LLM proposer alone missed.

**Unknown.** The routing decision itself. The test-repair SLR (41 primary studies) catalogues how to repair a test once you *know* it is broken, and offers nothing on deciding that it is. Cheng et al. (Google, 120 bugs) come closest with patch selectors that score the test change and code change *jointly*, but report parity rather than improved routing accuracy. Veri-Sure will have to build this from mechanical controls, not look it up.

### 2.6 Trace compression, minimisation, localization

**Established — a mismatch should arrive with its fan-in cone.** VerilogCoder (AAAI 2025) back-traces RVALUE dependencies through the AST from the mismatched signal to an **agent-chosen** depth and returns three things: source references, a **tabular waveform** of the mismatched signal across cycles, and the extracted driving signals (+11.5% pass rate with the baseline planner, +27.5% with theirs). MAGE (DAC 2025) contributes the granularity — a window around the *first* divergence, not the whole run.

**Established — the slicing decision should belong to the agent.** VeriTrace (ICLAD 2026) gives the debug agent free choice of `(signals, t_start, t_end)` and unbounded iteration depth, and gets **100% pass@1 on VerilogEval-V2 with an 18% token reduction** (26.7k → 21.9k), with a 5.2× reduction on one FSM problem (619.5k → 110.3k, pass@1 33% → 100%). On-demand slices *shrink* context rather than growing it.

**Established, and stronger than slicing — minimisation.** Zeller & Hildebrandt's ddmin returns a **1-minimal** failing input: every remaining element is individually necessary, which is a causal claim, not a heuristic view. The Mozilla case reduced **95 user actions to 3** and 896 HTML lines to 1 in 139 test runs — a *temporal* reduction, which answers whether this applies to clocked stimulus. MacIver & Donaldson (ECOOP 2020) solve the validity problem that would otherwise sink this on SystemVerilog: shrink the **choice sequence** that generated the test and re-run the generator, so every candidate is valid by construction. Keles et al. (2026) calibrate expectations: QuickCheck-style structural shrinking preserves only a 5–12% failure rate across steps (so ~9 in 10 re-runs are wasted), and integrated shrinkers did **not** dominate — pick the simplest one.

**Established — per-check verdicts sharpen localization for free.** Xuan & Monperrus (FSE 2014) split multi-assertion tests into single-assertion fragments across 1,800 faults; per-assertion spectra improve existing fault localization with no change to the algorithm. Veri-Sure accumulates many checks into one mismatch counter, so a failure yields one undifferentiated verdict.

**Unknown.** Nobody has published ddmin over SystemVerilog stimulus with a Verilator oracle. The closest points are Zeller's GUI sequences, Lee et al.'s delta debugging of gate-level *netlists* (to debug a synthesis tool), and Schuppan & Biere's length-minimal LTL counterexamples. Note also that `sby mode cover` literally produces "the set of shortest traces required to reach all cover() statements" — a minimal-witness generator sitting unused inside a tool Veri-Sure already runs.

### 2.7 Benchmarks and measurement

**Established.** A small real category scores *verification* rather than RTL: FIXME (180 tasks across six verification sub-domains, including testbench generation, reference-model generation and SVA generation, with per-sub-domain metrics), CVDP (783 problems, 13 categories; CID12 is testbench generation over 83 repos scored by **whether coverage exceeds a specialist-defined threshold**), VerifLLMBench (UVM, scored on build/coverage/lint), FVEval, and the AutoBench→CorrectBench→ConfiBench line. Everything else — VerilogEval, RTLLM, ChipVerilog, ChipBench, TuRTLe, RTL-Repo, MetRex — scores the RTL and treats the testbench as trusted infrastructure.

The invariant across every sound coverage-threshold benchmark: **the denominator and the threshold must be external to the artefact being scored.** UVM2's functional-coverage denominator is a covergroup written by human engineers; CVDP's threshold is specialist-defined; LLM4Cov assigns 0% coverage where simulation *fails*. Any Veri-Sure "PASSED-BUT-UNEXERCISED" verdict where the agent picks its own covergroup is self-report, not measurement.

**Contested — and one claim should be retired.** GoGoTB reports UVM2 at **0% environment-generation success on all 8 designs**. UVM2's own paper reports **86.67% generation success, 87.44% code / 89.58% functional coverage** under Synopsys VCS, and HAVEN independently places UVM2 only 3.6pp below itself on 9 overlapping designs. GoGoTB cloned the UVM2 repo into a Verilator+cocotb harness that cannot host the UVM class library and never states the simulator. **That is the identical pathology `sim_reviewer.py` already documents internally — a harness mathematically unable to return pass — arriving as external confirmation that every baseline needs a reference precheck.** Do not repeat the 0%.

**Unknown.** No benchmark scores **diagnostic/log quality** — whether a failure message carries expected-vs-actual, cycle, minimal stimulus, and localization. Every benchmark collapses a run to pass/fail or a coverage number. ChipBench's zero-shot vs one-shot (waveform-assisted) split over 89 debug cases is the only controlled instrument, and it varies the *input*, not the quality of the derived report. Given `trace_report.py` (889 LOC) and `trace_slicer.py` (592 LOC), this is both the repo's clearest unmeasured capability and a genuine contribution.

## 4. What this implies for Veri-Sure

### (a) Cheap wins — prompts, linting, verdict plumbing (this week)

1. **Negative control before any verdict is trusted.** `/home/user/Veri-Sure/eda_agent/tb_editor.py` already has `build_mock_dut()` / `mock_dut_review()` used as a *positive* control. **Invert it:** build a deliberately-wrong DUT (mutate the candidate, or tie outputs off) and require the TB to report a mismatch. A TB that passes both the candidate and a known-bad DUT is unsound and must be regenerated. One extra Verilator run per node, zero LLM calls, kills the mirrored-oracle and dead-check families at the root. This is the highest cost/benefit item in the whole report (Xu & Wu measured the analogous intervention at −7.8pp evidence-inadequate closure, p=0.0029).

2. **Positive control / reference precheck, and a third verdict class.** In `/home/user/Veri-Sure/eda_agent/sim_reviewer.py`, run the golden (or the last-passing revision) through the identical flow first. If it fails, emit `reference_fail`, not `function_fail`, and route to `tb_editor.py` with the RTL untouched. Add `UNDECIDED` (no recognised marker *and* no failure marker), `harness_error`, and `timeout` as first-class outcomes excluded from the RTL loop. **This is the recorded `====` incident, with a place to go.**

3. **Contractual verdict line — stop widening the PASS regex.** Require the TB to emit a fixed machine-defined summary line, checked at lint time in `/home/user/Veri-Sure/eda_agent/contract_linter.py`. Absence of that line is `harness_error`, never a design failure. Version and log the accepted marker grammar with every verdict; a scoring artefact then becomes identifiable after the fact.

4. **Add `--coverage` to the Verilator invocation** in `sim_reviewer.py` (`--coverage-line --coverage-toggle --coverage-fsm`), merge seeds with `verilator_coverage --write`, and render with `--annotate`. This closes two failure modes with one flag: uncovered-line lists (with file:line) are a far better repair payload for `/home/user/Veri-Sure/eda_agent/trace_report.py` than a trace slice, and **coverage on the mismatch-counter increment line is a provable dead-check detector** — PASS with zero hits on that line means the check never executed. Report **toggle** first: STG's data shows line coverage is near-saturated and uninformative, toggle is what discriminates.

5. **Cover-the-antecedent for every assertion.** In `/home/user/Veri-Sure/eda_agent/asserter.py`, emit `cover(A)` for every `assert(A |-> B)`; `/home/user/Veri-Sure/eda_agent/boolean_proofer.py` decides reachability. An unreachable antecedent is DEAD, not PASSED. Also: attempt `sby mode prove` (k-induction, unbounded) before falling back to `mode bmc`, and record **proved / bounded-clean-to-depth-k / refuted** as three distinct verdicts. And treat an unreachable-within-depth cover as UNKNOWN, never FAIL — that is "bounded-cover vacuity."

6. **Context-construction independence.** Audit what `/home/user/Veri-Sure/eda_agent/tb_generator.py` and especially `tb_editor.py` (1552 LOC, the higher-risk surface) actually receive. The rule becomes an invariant, not a request: **TB generation and TB repair are conditioned on the architect contract only, never on `rtl_generator` output**; where port information is needed, pass an interface stub. Add the corollary rules with published backing: no hierarchical `force`/`release` into the DUT and no submodule instantiation from the TB (CovAgent), and a `#1` delay separating stimulus from checking on the same clock edge (the race STG found in VerilogEval's own testbenches — a statically checkable rule and a direct cause of intermittent false FAILs).

7. **Fix the two repair loops' control.** At `/home/user/Veri-Sure/eda_agent/top_agent.py:628-648` the TB lint loop *accumulates* errors across retries; LLM4DV's ablation says accumulating a poisoned history makes models repeat prior mistakes. Add a stall detector (no new information in *t* iterations → wipe and restart from the system prompt, retaining only the best-scoring prior attempt) and cap at **3–4 iterations** (two independent studies put the knee there). Tier the lint gates hard/soft/advisory and soften on retry so a cosmetic rule cannot starve a node.

8. **Graded fitness instead of a boolean.** `sim_reviewer.py` already parses `Mismatches: N in M samples` — expose `N/M` and `M>0` to `rtl_generator.set_failed_trial()`. A run with `M == 0` must never be a PASS regardless of markers. Add a strict-improvement guard so an edit that worsens the ratio is reverted (this would have caught the `always_ff` → `always_comb` rewrite that broke the 1-cycle latency contract).

9. **Per-check IDs.** Give every check a stable identifier and report a per-check pass/fail vector, not just a total. `trace_slicer.py` can then slice against the signals of the *specific* check that fired, and a check that never fires across any run is mechanically detectable.

### (b) Medium work — new modules

10. **`tb_qualifier.py` — the mutation admission gate.** Deterministic, seeded, first-order syntactic mutants over GateTruth/Hampton's operator set (relational/logical operator swap, force an `if`/`case` condition, delete a non-blocking assignment, delete a case item, reset/enable polarity flip, output inversion, register-hold). Pipeline order, each stage cheap-before-expensive: **formal equivalence filter** (Yosys, via `boolean_proofer.py` — provably-equivalent mutants leave the denominator, no exclusion table) → **statistical sampling** (Leveugle: ~40–100 mutants at ±10% in-loop, tighten only for reports) → **activation pre-filter** (mutant stdout/VCD byte-identical to golden ⇒ never spend the detection run) → **nested fault dropping** → detection runs. Report the **four-status verdict** (not-activated / not-propagated / not-detected / detected) as the repair routing key, and a **stillborn** rule (non-compiling mutants leave the denominator). Gate on **raw kill count**. Hold out a disjoint mutant set from `tb_editor.py` — GateTruth observed a Goodhart effect the moment its gate became a target. Budget guidance from Busch: mutate only the module the current node owns; cost is multiplicative in (sites × checks) and partitioning bought a 10× reduction.

11. **`tb_planner.py` + `tb_render.py` — split `tb_generator.py`.** The LLM emits a structured plan (scenarios over GoGoTB's D1–D7, cover_bins, expected-value rules, stimulus as a bounded *choice list*); deterministic Python renders the SystemVerilog. The renderer — not the model — owns the module header, clock/reset, mismatch counter and verdict printing, and those live in a **protected set** `tb_editor.py` may never touch. This is the single change that makes the accreted prompt rules unnecessary rather than merely enforced (no-`automatic`-on-procedural-init, no SV `string` comparison under Verilator, exactly one top-level module), and **it would have prevented the "5 of 30 oracles could never print an accepted marker" incident outright.** HAVEN's evidence: 100% compilation across 19 designs at $0.37/design. Include loops, conditional stalls and backpressure in the DSL from day one — HAVEN's linear DSL hit an expressiveness ceiling on 15.8% of designs, exactly the protocol-sequencing case ChipVerilog's or1200/mips families are made of.

12. **Stimulus minimisation (ddmin over the choice list).** Once (11) exists, minimisation is a search over the choice sequence and every candidate compiles by construction (MacIver & Donaldson). Define `test(subsequence) = same check still fires`, shrink to 1-minimal, and feed *that* to `rtl_generator.set_failed_trial()` instead of the sim log. Budget note: expect ~90% of shrink candidates to pass and be wasted, so **compile once with stimulus read from a file/plusarg and re-run the binary per candidate** (Lee et al.: 2× fewer oracle calls, 10× speedup from exactly this integration). Also track already-minimised counterexamples so the loop surfaces the second bug instead of re-finding the first.

13. **Diagnostic structuring layer around Verilator/make.** Every tool invocation returns through guard → structure → validate, producing typed records; if no record can be produced, that is a distinct verdict, not a design failure. This generalises `_TOOLCHAIN_ERROR_RE` from a heuristic into a component, and Verilator's own documented warning classes (`UNSUPPORTED`, `MULTIDRIVEN`, `WIDTHEXPAND`, `BLKSEQ`…) are a free, enumerable taxonomy to key an error-signature → guidance table on (RTLFixer's approach: ~98.5% of 212 compilation errors resolved). CovAgent measured the payoff at 4–13× token reduction.

14. **Blame-attribution / dialectical arbiter in `top_agent.py`.** Insert before `set_failed_trial()` at line 895 a step whose only output is `{rtl_bug | tb_bug | contract_bug | toolchain}`, using the M1/M2 results, the mutation four-status, and the contract as inputs — not the RTL alone. Fire it only after *N* failed repair attempts (SpecLoop's retry-before-blame budget) so it does not run on ordinary first-try bugs. PRO-V measured +2.5pp from componentising this decision; it is the general form of the "name a self-contradicting oracle" commit.

15. **Agent-callable trace tool.** Refactor `trace_report.build_trace_report()` into `trace_query(signals, t_start, t_end)` over the existing `_vcd_*` helpers, and expose it to the debug agent. VeriTrace's result is that this *reduces* tokens by ~18% while raising pass@1, because on-demand slices replace speculative dumps. Layer VerilogCoder's structural default underneath: AST fan-in cone from the mismatched signal to an **agent-chosen** depth, returned as source refs + a **tabular waveform**, not a single point sample. And add the missing third field everywhere: `{location, observed value, admissible alternatives}` — for a mismatch, the contract clause that determined the expected value; for a toolchain error, the lowerable construct set.

### (c) Research bets

16. **Formal discharge of unreachable coverage bins.** For each uncovered bin, assert the negation of its condition and run `sby mode prove`; PASS ⇒ genuinely unreachable, leaves the denominator *with its proof and assumption set recorded*; UNKNOWN or counterexample ⇒ real hole. Nobody in the LLM coverage literature does this — GoGoTB removes bins with no criterion, CovAgent admits its ceilings are unvalidated, NOVA is deflated by them. Synopsys has productised the workflow, so the shape is proven; doing it with free tools is the contribution. Inherited warning: an exclusion proved under a wrong constraint environment is indistinguishable from a real one, so re-check when `contract_linter.py`'s contract changes.

17. **Formal↔simulation cross-oracle adjudication.** Where SymbiYosys proves a composition correct and the TB nonetheless fails it, you have a **free proof that the oracle is wrong**. Veri-Sure has `boolean_proofer.py`, `asserter.py` and `sim_reviewer.py` in one process and ChipVerilog's oracle mix is 56.9% equivalence — the ingredients are unusually well placed. This is the exact case the known "proven-correct composition scored a DESIGN FAILURE" incident needed, and no paper does it (GateTruth explicitly *discards* the signal by separating formal from simulation kills).

18. **Coverage-guided mutation fuzzing with a frozen oracle.** The expensive artefact is the checker, not the stimulus. Once a TB clears its admission gates, freeze it (GoGoTB's oracle-immutability policy — also a structural bar on reward hacking) and search stimulus mechanically by mutation under Verilator's coverage feedback, terminating on a coverage plateau rather than an iteration count. RFUZZ established the RTL formulation; **no 2026 LLM paper uses it**, and it costs zero tokens.

19. **Repair cross-validation as a standing metric.** Withhold a portion of TB checks (or the golden TB) from the repair loop and score final RTL against them. The in-loop minus held-out gap *is* the overfitting number — the quantity that determines whether Veri-Sure's headline pass rate is a measurement or a self-report.

20. **Metamorphic checks for RTL.** Require `tb_planner` to emit at least one MR per node from a fixed pattern set: **timing invariance** (insert stalls / extend inter-transaction gaps / delay `valid` by *k* — the result *sequence* must be unchanged), reset idempotence, scaling/linearity (double_fpu, cordic), superposition, monotonicity (counters, FIFO occupancy, comparators), commutativity of independent transactions. An MR constrains the DUT against itself, so it **structurally cannot mirror the DUT's algorithm**. Ayerdi et al. measured MR oracles at 88.76% mutation score vs a reference-model oracle's 52.8%, at roughly a third the runtime — and reported their false-positive rate (0.19–0.24%) alongside, which is the two-sided honesty to copy.

## 5. Working with ChipVerilog

**What it is good for.** ChipVerilog's harness already implements two mechanisms Veri-Sure should adopt outright — the **reference precheck** (`reference_fail`, not `function_fail`) and **timeout exclusion** ("a timeout proves nothing about the candidate") — plus a **static self-checking gate** (`tb_is_self_checking()`: some string literal must be able to express a fail verdict). Its 64 OpenCores-derived reference designs are the raw material for everything in §4: they are goldens you can mutate, and they span the size class (several >1000 LOC) where every other benchmark stops.

**What it cannot measure.** ChipVerilog is an *RTL-generation* benchmark under a mostly-formal oracle. Verified: only **16 of 64 task dirs ship a testbench** (12 self-checking, 4 print-only), and the verdict mix is **56.9% formal equivalence / 30.7% compile gate / 12.4% simulation TB**. So a headline ChipVerilog score moves almost entirely for reasons unrelated to TB quality, and TB hardening will barely register on it. Two further caveats: **383 of 431 proof-typed verdicts are `bounded_seq`**, so most "formal" verdicts are bounded and (per Kroening et al.) carry no completeness claim; and the flow is `iverilog`/`vvp`/`yosys` with **no coverage instrumentation at all**, so none of §2.3's metrics are computable until Verilator is stood up on those targets (a real porting cost — SystemVerilog support differs, and or1200 sources may not elaborate cleanly).

**The structural mismatch to design around.** ChipVerilog's flow assumes a reference and asks "does the candidate match it." A Veri-Sure run **generates its own TB**, so the oracle under test is the artefact ChipVerilog treats as fixed infrastructure. Using it unmodified measures Veri-Sure's RTL agent, not its TB agent.

**How to use it to measure TB hardening.** Turn ChipVerilog inside out — score the *testbench* against the reference, in four measurements:

1. **M1, false-FAIL rate (completeness).** For every task with a reference, generate a TB from the contract and run it against the **reference RTL**. Any failure is a `reference_fail` and is a TB defect. This is directly available for all 64 references and is the cheapest, most informative number Veri-Sure can produce this week.
2. **M2, kill rate (soundness).** Mutate each reference with the deterministic operator set, filter equivalents formally, sample ~40–100, and measure kills. Report **raw** counts and the four-status breakdown. GateTruth's 95% floor is the defensible threshold; expect the first run to be embarrassing (RTLLM's own testbenches pool at 56.8%).
3. **Baseline calibration on RTLLM v2.0 rather than ChipVerilog.** RTLLM is MIT-licensed (ChipVerilog is CC BY-NC-SA) *and* GateTruth published per-design kill rates for its 46 auditable designs. That gives ground truth for which reference TBs are weak, so you can ask the sharp question: **does a Veri-Sure-generated TB beat the RTLLM reference TB's kill rate?** That converts the prompt-rule list from folklore into a measurable curve.
4. **Coverage-threshold verdict, denominator sourced externally.** Follow CVDP CID12: derive the per-task coverage threshold **once from the reference run** and store it as task metadata. The agent must never author its own covergroup *and* its own threshold — that is self-report. Assign 0% where simulation fails (LLM4Cov's convention).

**And audit your own benchmark first.** `VerilogEval-v2-EXT`'s 53 added tasks are the surface on which Veri-Sure's headline functional pass@1 is reported, and those testbenches have never been mutation-audited or reference-prechecked. Given that 72% of RTLLM v2.0's designs fall below a 95% kill floor and three score 0%, the prior that some EXT testbenches are dead is high — and a dead reference TB inflates exactly the number the paper claims credit for. Run M1 and M2 on the EXT set before anything else. (Also worth pinning down: the ChipVerilog paper's Table 4 and this session's `reproduce_metrics.py` output disagree on Opus 4.5 by ~0.3/0.6 points; resolve the metric definition before either is quoted.)

**Pair it.** ChipVerilog measures generation; **FIXME** (180 tasks, six verification sub-domains including testbench generation and reference-model generation, with fault-injected designs in its Debug track) and **CVDP** (783 problems, engineer-authored SystemVerilog testbench tasks, agentic Docker harness) measure the verification artefact as the deliverable. HWE-Bench (417 repo-level tasks judged by each project's *own* native regression flow) is the one benchmark where a false PASS is impossible by construction — making it a clean control for estimating `sim_reviewer.py`'s false-pass rate elsewhere.

## 6. Open questions and where the literature is thin

- **The verdict channel is unstudied.** Every system assumes that once a check decides correctly, the verdict reaches the harness intact. Veri-Sure's most expensive incident is the opposite. GateTruth's disclosed fail-open bug (a missing mount made every mutant fail identically, "capable of reporting a false 100% kill rate with a zero exit code") is the only published analogue, and it is a self-audit footnote. There is no literature on machine-readable verdict protocols versus ad-hoc log-marker parsing. **Veri-Sure has more field evidence here than anyone published**, and the fix — make the verdict a rendered template artefact rather than LLM-authored text — is not in the literature at all.
- **Nobody measures coverage of the TESTBENCH.** Spec2Cov, GoGoTB, LLM4Cov, CovAgent, HAVEN and LLM4DV all instrument the DUT. Not one instruments the checker. Yet every dead-check failure is an uncovered TB line, and Verilator will instrument tb.sv as readily as rtl.sv. **A one-flag experiment nobody has run.**
- **No benchmark scores failure-log actionability.** Testbench quality is universally scored on verdict correctness. For an agentic loop the more binding constraint is whether the failure output lets a downstream agent localise and fix — and that is unmeasured everywhere.
- **The two-loop routing decision has no published treatment.** Test-generation papers assume the code is ground truth; repair papers assume the tests are. The 41-study test-repair SLR catalogues how to repair a test once you know it is broken and offers nothing on deciding that it is. Cheng et al.'s joint patch selectors are the closest and report parity, not accuracy. This is the gap Veri-Sure actually sits in.
- **Correlated hallucination is named but not measured.** RefEvo names it; CorrectBench's method assumes errors distribute randomly across sampled implementations; nobody measures whether that population *is* independent. For Veri-Sure the assumption is weaker than in CorrectBench, because the TB and RTL agents share the architect contract — and ChipVerilog's OpenCores targets are very likely in pretraining data.
- **Bounded proofs are treated as proofs.** ChipVerilog records 383 `bounded_seq` verdicts and never states a depth or discusses the caveat; RTL-BenchLS advertises testbench-free LEC/SEC certification without publishing a bound. Only the industrial formal literature (Kumar, DVCon 2023 — helper assertions, abstraction, k-induction to escape a bounded result) is honest about it. There is also no published account of **confidence composition across heterogeneous oracles** of differing strength (full proof / bounded proof / mutation-gated sim / self-checking sim / compile gate), which is exactly the reduction Veri-Sure must perform.
- **Simulator-lowering failures are unstudied as a class.** LLM-written SystemVerilog that is legal per the LRM but mis-lowered by the target simulator, producing an error at the wrong abstraction level with no source attribution, appears nowhere. Every system assumes VCS/Xcelium (HAVEN, UVM2, LLM4Cov, CHORUS, NOVA) or iverilog (ChipVerilog, GateTruth). A Verilator-targeted TB lint rule set is unpublished work Veri-Sure needs regardless.
- **Intra-model discrimination of mutation score is unvalidated.** The r=0.863 result ranks *generators*, not two same-model TBs for one node — which is Veri-Sure's actual use. Cheap to test internally, and it determines whether the gate belongs per-node or per-configuration.
- **The cost asymmetry between false-FAIL and false-PASS is unquantified for Veri-Sure.** Nobody reports "iterations burned on correct RTL because the oracle was wrong." Veri-Sure has the telemetry to measure it, and it determines which side of Barr's soundness/completeness trade-off to tune toward.
- **The accreted prompt rules have never been ablated, and the one relevant data point is a warning.** Bodicoat et al. found chain-of-thought and tree-of-thoughts cut oracle compilation from ~67–73% to ~44% and accuracy from ~52–55% to ~29–31% versus zero-shot. VerilogReader's hand-written test guidance *backfired* on 2 of 8 designs by "reducing the diversity of LLM-generated input... stifling its capacity for self-exploration." `/home/user/Veri-Sure/eda_agent/prompts.py` (904 LOC) plus `tb_generator.py`'s SYSTEM_PROMPT is a monotonically growing incident log with no regression test. **The most informative experiment available is an A/B of prompt variants against a fixed panel of known-good and known-bad RTLs, scored two-sided (kill rate and false-FAIL rate).** That single harness would convert the whole rule list from folklore into a versioned, testable artefact — which is what "systematic rather than whack-a-mole" actually requires.
